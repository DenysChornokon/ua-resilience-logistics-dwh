# 37. Передача та повторний запуск

## Склад комплекту

Комплект створюється **локально** і має окремі частини:

- `project_code.zip` — відстежувані Git-файли з конкретного коміту: код, інструкції, результати та графіки;
- `LOCAL_private_data.zip` — локальні файли з `data/raw`, `data/processed`, `data/synthetic`, включно з великими модельними наборами;
- `manifest.json` — версія коміту, перелік файлів, розміри та SHA-256;
- `handoff.py` — окрема утиліта перевірки й відновлення, для якої достатньо стандартної бібліотеки Python 3.13;
- `ПРОЧИТАЙТЕ.md` — коротка інструкція для отримувача.

**Архів даних містить неофіційний спрощений файл районів, умови поширення саме цієї обробленої копії не встановлені.** Він призначений як локальна копія власника; перед передачею іншим особам потрібно окремо перевірити права на цей та інші зовнішні дані. Походження й атрибуція — у [документі 27](27_district_context.md). Саме створення локальної копії не є передачею третім особам.

Файл `.env`, паролі, Docker-томи, середовище `.venv` та історію Git комплект не містить. Архів даних **не зашифрований**. Архів коду — знімок, а не клон із історією. Контрольні суми допомагають виявити пошкодження, але не є цифровим підписом і не підтверджують автентичності, якщо сам manifest було замінено. Копія на тому самому диску не захищає від його втрати: за потреби збережіть її на окремому захищеному носії.

## Створити й перевірити локальний комплект

Потрібні Git, Python 3.13, чиста робоча гілка та локальні дані проєкту. Команда бере код саме з `HEAD`, відхиляє незакомічені зміни, не копіює `.env` і перевіряє контрольні суми кожного файла до й після створення. Вкажіть **нову папку поза проєктом**:

```powershell
.\.venv\Scripts\python.exe -m scripts.handoff_bundle build `
  --output C:\Temp\dwh-handoff-01
py -3.13 C:\Temp\dwh-handoff-01\handoff.py verify --bundle C:\Temp\dwh-handoff-01
```

Програма не перезаписує наявний комплект і відмовляється копіювати символічні посилання або файли, схожі на секрети. Помилка означає, що комплект не слід вважати завершеним; створіть нову папку після усунення причини. Дані й код є окремими архівами, а перелік файлів — у `manifest.json`.

## Відновити копію без Git

На комп'ютері з Python 3.13 спочатку перевірте комплект, потім відновіть обидва архіви в **нову, ще не створену** папку:

```powershell
py -3.13 C:\Temp\dwh-handoff-01\handoff.py verify --bundle C:\Temp\dwh-handoff-01
py -3.13 C:\Temp\dwh-handoff-01\handoff.py restore `
  --bundle C:\Temp\dwh-handoff-01 --destination C:\Temp\dwh-restored-01
cd C:\Temp\dwh-restored-01
```

Кожен файл перевіряється за manifest; наявна папка призначення не перезаписується. Якщо відновлення перерветься, частково створена нова папка може залишитися; для повтору виберіть іншу нову назву. Відновлена таким способом папка не містить історії Git.

Якщо потрібен Git, можна окремо клонувати репозиторій і перейти до **точного коміту з `manifest.json`**. На чистій робочій копії команда нижче додасть тільки дані, перевіривши коміт; наявні однакові файли вона пропускає, а відмінні не перезаписує:

```powershell
py -3.13 C:\Temp\dwh-handoff-01\handoff.py restore-data `
  --bundle C:\Temp\dwh-handoff-01 --destination C:\шлях\до\чистої-Git-копії
```

## Створити нові бази та перевірити дані

Працюйте з відновленою **новою копією**, а не з наявною робочою папкою. Встановіть Python 3.13, Git (потрібен для окремої перевірки чистого розгортання) і Docker Desktop. Далі в PowerShell із кореня відновленої папки:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Запустіть Docker Desktop, дочекайтеся готовності й виконайте:

```powershell
.\.venv\Scripts\python.exe -m scripts.setup_handoff_demo
```

Команда перевіряє файли й конфігурацію, обирає випадкову **нову** назву Compose-проєкту, створює `.env` із новим паролем та окремі томи, завантажує дані й запускає перевірку демонстрації. Вона не перезаписує наявний `.env`, не використовує наявні бази й не видаляє томи. Стандартні локальні порти — **55434** для `logistics_dwh` та **55435** для `spatial_research`; вони мають бути вільні. Інші вільні порти можна задати параметрами `--core-port 55436 --spatial-port 55437`.

Успішний результат містить `"status": "ready"`. Після цього відкрийте pgAdmin і скористайтеся [інструкцією перевірки даних](35_pgadmin_demo.md), але для цієї відновленої копії вкажіть порти **55434 / 55435** або обрані параметрами. Решта параметрів підключення такі самі; новий пароль міститься у **локальному** `.env` відновленої копії. Не включайте його до передачі. Час у знімку й ідентифікатор активної версії після відновлення будуть новими.

Надалі для запуску вже створених контейнерів саме відновленої копії з її кореня використовуйте:

```powershell
docker compose --profile spatial-research start db spatial-db
.\.venv\Scripts\python.exe -m scripts.verify_demo
```

Якщо початкова ініціалізація перервалася, `.env`, журнал `.handoff-setup.log` і нові ресурси залишаються для діагностики. Повторний запуск ініціалізації поверх них заблокований; не видаляйте томи з даними без розуміння їхнього призначення. Потрібні образи Docker можуть завантажуватися з мережі, як і Python-пакети; доступність залежить від середовища.

## Межі результату

Дані синтетичних доставок, координат і відключень не є реальними спостереженнями. Районний шар не є підтвердженою офіційною геометрією; погода характеризує одну модельну точку. Сценарій відновлення створює нові бази з підготовлених джерел, а не копіює початкові Docker-томи, їхні історичні ID чи облікові дані. Для постійної роботи й оновлення джерел потрібні окремі рішення. Перевірка на тому самому комп'ютері не доводить працездатності на будь-якій іншій ОС або без доступу до залежностей.

17.11.2026 пробний комплект перевірено на цьому комп'ютері: відновлено файли в нову папку й окремо в чисту Git-копію, створено нові бази, перевірено підключення та демонстрацію після перезапуску. Тестові бази прибрано. Звіт — `reports/handoff_validation_20261117.json`; він стосується тимчасового тестового знімка, а кожен фактичний комплект потрібно окремо перевіряти за його manifest.
