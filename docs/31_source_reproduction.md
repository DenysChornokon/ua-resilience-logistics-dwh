# 31. Відновлення основних даних із локальних джерел

## Результат перевірки

11.11.2026 три основні CSV відтворено на цьому комп'ютері з локальних копій первинних JSON та генератора синтетичних доставок. Результати порівняно з файлами, які використовувалися в дослідах:

| Набір | Походження | Рядків | Збіг із наявним CSV |
|---|---|---:|---|
| Тривоги | Збережений JSON, нормалізація `Europe/Kyiv` → UTC | 371 | Значення, порядок і байти збіглися |
| Погода | Збережений JSON Open-Meteo, GMT → UTC | 2 208 | Значення, порядок і байти збіглися |
| Доставки | Генератор із `seed=42` | 500 | Значення, порядок і байти збіглися |

Додатково виконано режим створення у папці, що містила **лише два вхідних JSON і жодного готового CSV**. Усі три файли побудовано та перевірено правилами завантажувача. Їхні SHA-256 окремо збіглися з контрольними сумами наявних файлів. Звіти — `reports/source_reproduction_20261111.json` і `reports/source_build_only_20261111.json`.

Використано Python 3.13.3, pandas 3.1.0 та NumPy 2.5.4 із наявного середовища. Звіти містять контрольні суми вхідних JSON, коду й результатів та версії бібліотек. Контрольні суми коду залежать від фактичних байтів файлів, зокрема можливих перетворень закінчень рядків Git у Windows.

## Як повторити

Потрібні встановлені залежності з `requirements.txt` і файли:

- `data/raw/alerts/airAlert_2026-10-26.json`;
- `data/raw/weather/kyiv_weather.json`.

Вони виключені з Git. Для режиму порівняння додатково потрібні наявні три CSV за шляхами з документа 30. Скрипт працює без мережі та бази даних. Папка для результату повинна **ще не існувати**; туди копіюються JSON, створюються CSV та `source_reproduction_report.json`.

Із кореня проєкту, щоб відновити й порівняти з наявними CSV:

```powershell
.\.venv\Scripts\python.exe -m scripts.verify_source_reproduction `
  --output-dir C:\Temp\dwh-source-compare-01
```

Щоб створити CSV, коли готових файлів немає, використовуйте:

```powershell
.\.venv\Scripts\python.exe -m scripts.verify_source_reproduction `
  --build-only --output-dir C:\Temp\dwh-source-build-01
```

За потреби `--source-root C:\шлях\до\папки` вказує іншу папку, у якій JSON лежать за наведеними вище відносними шляхами. У режимі `--build-only` статус `built_uncompared` означає, що файли перевірено на відповідність правилам завантаження, **але автоматичного порівняння з попередніми CSV не виконано**. У режимі порівняння `matched` означає збіг полів CSV та їхнього порядку; рівність точних байтів відображено окремо. Це важливо: просторовий генератор із документа 26 додатково вимагає точний SHA-256 доставок.

Скрипт не перезаписує вихідні файли, перевіряє їхні контрольні суми до та після роботи. Перед перетворенням погоди перевіряються нульове UTC-зміщення, часовий пояс, одиниці, розміри масивів і приблизна близькість точки сітки до Києва. Близькість не доводить точність погоди або справжність джерела. Для отримання результатів у робочому проєкті потрібне окреме обережне перенесення створених файлів із нової папки; сама команда їх не підміняє.

## Межі результату

Перевірено **збережені локальні знімки**, а не повторне завантаження джерел з інтернету. Доступність первинного джерела тривог після втрати цього JSON і незмінність зовнішніх сервісів не підтверджено. Чисту інсталяцію Python/ОС, відновлення геоданих і повторення великих benchmark-наборів у цьому кроці не перевірено. Погодні дані є модельними даними для однієї точки, доставки — синтетичними. Вихідний час тривог трактуємо як київський за підтвердженням користувача. Районні межі залишаються дослідними, як описано в документі 29.
