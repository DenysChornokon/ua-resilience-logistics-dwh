# 06. Початкове завантаження CSV у PostgreSQL

Цей крок переносить підготовлені дані PoC до PostgreSQL та реєструє успішні завантаження. Просторового join, погодних агрегатів і вітрини експозиції він ще не реалізує.

## Передумови

- Docker Desktop запущено; із кореня проєкту `docker compose up -d` запускає сервіс `db`.
- Структуру створено командою `docker compose exec -T db psql -U dwh_user -d logistics_dwh -v ON_ERROR_STOP=1 -f /sql/01_create_schema.sql`.
- Наявні файли `data/processed/alerts.csv`, `data/synthetic/deliveries.csv`, `data/processed/kyiv_weather.csv`. Файли в `data/` виключені з Git, тому після клонування їх потрібно отримати або підготувати окремо.
- Python використовує тільки стандартну бібліотеку для завантаження. Дані передаються у `psql` всередині контейнера через Docker Compose; пароль із `.env` не потрібно передавати в команді Python.

## Запуск

Із кореня проєкту:

```powershell
python -m scripts.load_dwh --validate-only
python -m scripts.load_dwh
```

Перший виклик перевіряє файли без підключення до бази. Другий спочатку повторює перевірку, а потім завантажує усі три набори в одній транзакції. Для поточного зрізу очікуються **371 тривога, 500 доставок, 2 208 погодинних записів**. Це контрольні значення поточного набору, а не вимога для кожного майбутнього файлу.

Вихід `LOADED` означає успішне початкове завантаження. `UNCHANGED` означає, що в таблицях уже є дані з такими самими хешами файлів, очікуваними кількостями і записами про походження: повторний запуск не додає дублікатів. Якщо наявні факти мають інші джерела або неповний склад, скрипт завершується з помилкою і не перезаписує їх. Оновлення іншого зрізу потребує окремо спроєктованого механізму.

## Перевірки і правила

Порівнюються назви колонок, обов'язкові поля, ключі, код регіону, тип тривоги і статуси; перевіряються часові пояси, напіввідкриті інтервали в UTC-вікні, числові значення та повнота погодинного ряду. Пошкоджений файл або відхилений рядок зупиняє завантаження **до зміни бази**: у терміналі наведено кількість помилок, файл, номер рядка та причину. Помилки не пропускаються мовчки. Окремої таблиці відхилених рядків цей початковий варіант ще не створює.

Рядки трьох CSV передаються у тимчасові таблиці PostgreSQL, після чого записуються у `core` та `control.load_batch`. Транзакція й блокування взаємного запуску захищають від часткового завантаження та одночасного дублювання. Якщо SQL-запит завершується помилкою, транзакція скасовується; окремий запис про невдалу спробу в `control.load_batch` наразі не створюється. Для кожного успішного файлу зберігаються шлях, SHA-256, кількість рядків, версія трансформації і стан. На вході тривог зберігається припущення `Europe/Kyiv` і `timezone_verified = false`.

Погода описує одну точку Open-Meteo з координатами запиту `50.4501, 30.5234`. Доставки синтетичні. Вихідний час тривог вважається місцевим київським за рішенням користувача; це ще не підтверджено розпорядником. Скрипт завантажує вже підготовлений UTC CSV і не перетворює сирі часові мітки повторно.

## Перевірка в pgAdmin

Створи підключення до сервера за параметрами:

| Параметр | Значення |
|---|---|
| Host | `127.0.0.1` |
| Port | `55432` |
| Maintenance database | `logistics_dwh` |
| Username | `dwh_user` |
| Password | Значення `POSTGRES_PASSWORD` із локального `.env` |

Ця адреса підходить, коли pgAdmin запущено на тому самому комп'ютері, що Docker Desktop. Якщо pgAdmin працює в окремому контейнері, потрібні інші мережеві налаштування.

У Query Tool можна виконати:

```sql
SELECT 'deliveries' AS dataset, COUNT(*) AS rows FROM core.fact_delivery
UNION ALL
SELECT 'alerts', COUNT(*) FROM core.fact_alert
UNION ALL
SELECT 'weather', COUNT(*) FROM core.fact_weather_hour;
```

```sql
SELECT load_id, source_type, source_file, rows_read, rows_accepted,
       rows_rejected, status, source_timezone_assumption, timezone_verified
FROM control.load_batch
ORDER BY load_id;
```

Запуск тестів із кореня проєкту: `python -m pytest -q`. Перевірка вітрини експозиції та геометричних зв'язків належить до наступних етапів.
