# 26. Перший просторовий дослід PostGIS

## Джерело та його обмеження

У наявному файлі `data/raw/geography/geoBoundaries-UKR-ADM2.geojson` — 495 полігональних об'єктів ADM2, серед них один із назвою `Kyiv` і `shapeID = 74538382B60890943260132`. Це не набір із десяти міських районів. Локальний файл має SHA-256 `34f1a1486c1b6126a3d79c010dbb8398edf495d1688066e3e975c25573dbad10`; він збігається з LFS-контрольною сумою [оригіналу geoBoundaries](https://github.com/wmgeolab/geoBoundaries/blob/9469f09/releaseData/gbOpen/UKR/ADM2/geoBoundaries-UKR-ADM2.geojson). [Метадані цього набору](https://www.geoboundaries.org/api/current/gbOpen/UKR/ADM2/) вказують, що він відображає **2006 рік**; джерело зазначає Public Domain. Рік метаданих установлено за збігом ідентифікатора набору та контрольної суми файлу з опублікованим об'єктом на вказаному коміті. Поточність меж для 2026 року не підтверджена.

Файл використовує CRS84 — координати в порядку довгота, широта. Для PostGIS геометрію завантажено як `geometry(Polygon,4326)` із таким самим порядком координат; геометричних перетворень або обчислення площі в градусах не виконувалося. Валідність полігона за `ST_IsValid` підтверджує лише геометричну коректність, а не правовий статус чи відповідність сучасній межі. Зв'язок історичного `shapeID` із сучасним `region_id` є умовою синтетичного досліду, а не підтвердженою відповідністю КАТОТТГ.

На міському геопорталі знайдено [опис шару «Райони Києва»](https://gisserver-stage.kyivcity.gov.ua/mayno/rest/services/adge/Dilnyci/FeatureServer/2), у якому наведені назви міських районів. Це потенційне джерело, але під час перевірки домен сервера не розв'язувався з комп'ютера проєкту, геометрії отримати не вдалося, а опис шару не містив року й умов використання. Тому його ще не завантажено й не визнано перевіреним джерелом. Для районного аналізу потрібно отримати доступний набір і перевірити походження, дату, ліцензію та геометрії.

## Реалізація

Додано окремий сервіс `spatial-db` із PostgreSQL 17.11 та PostGIS 3.6.4 у `compose.spatial.yaml`. Він має власний Docker-том і базу `spatial_research`; наявна база `logistics_dwh` лишається на своєму томі. Контейнер просторового досліду слухає лише `127.0.0.1:55433`, використовує користувача `dwh_user` і пароль із проєктного `.env`. Образ зафіксовано за SHA-256; окремий том не призначений для підключення до старого контейнера.

`scripts.prepare_spatial_research` перевіряє контрольні суми історичного GeoJSON і раніше підготовлених 500 синтетичних доставок, потім для кожної доставки генерує відтворювану синтетичну точку всередині історичного полігона (`seed=42`). Вибірка рівномірна в координатній рамці з відхиленням точок поза полігоном; це не модель населення, адрес, маршрутів або рівномірності площі. Час і ID беруться з синтетичних доставок; координати не є їхніми реальними місцями. Файли й manifest записуються до `data/synthetic/spatial_research/`, яке виключено з Git. Наявні файли не перезаписуються.

`scripts.load_spatial_research` ще раз відтворює й перевіряє всі точки і manifest, після чого однією транзакцією створює в окремій базі історичний полігон, синтетичні точки, GiST-індекси та представлення `spatial_research.delivery_region`. Якщо об'єкти вже існують, завантаження припиняється без їх заміни. `ST_Covers` враховує точку на межі як збіг; незнайдена точка залишається в результаті з `within_historical_shape = false` і порожнім `matched_shape_id`. Правило межі не розв'язує неоднозначність між кількома сусідніми полігонами — цей дослід має лише один полігон.

## Перевірка

Після завантаження `scripts.verify_spatial_research` звірив джерела, геометрію в базі з GeoJSON, валідність та SRID, а всі 500 результатів — з незалежним Python-алгоритмом визначення точки в полігоні. **500 із 500 синтетичних точок зіставлено**; це очікуваний результат, адже їх навмисно згенеровано всередині контуру, і він не вимірює точності реальних доставок. Погодна точка запиту також лежить у цій історичній геометрії; це не доводить її розташування в сучасних межах.

Тест у транзакції з відкатом перевірив, що точка на межі включається, а точка поза полігоном зберігається без відповідності. Додатково перевірено різницю між `ST_Covers` і `ST_Contains` на межі. Результати і контрольні суми — у `reports/spatial_research_validation_20261110.json`. У початковій базі після досліду залишилися 500 доставок, 371 тривога і 2 208 погодних записів. Це не benchmark продуктивності: один полігон і 500 точок недостатні для висновку про прискорення просторового індексу.

## Відтворення

Потрібні Docker Desktop, `.env` з `POSTGRES_PASSWORD`, зафіксовані джерела GeoJSON і CSV синтетичних доставок із попередніх кроків та вільний порт 55433:

```powershell
docker compose -f compose.yaml -f compose.spatial.yaml --profile spatial-research up -d spatial-db
python -m scripts.prepare_spatial_research
python -m scripts.load_spatial_research
python -m scripts.verify_spatial_research
```

Друга і третя команди призначені для початкового створення даних і не перезаписують наявні файли або об'єкти. Якщо дані вже підготовлено й завантажено, для повторної перевірки достатньо останньої команди. Після використання можна зупинити **лише** додатковий сервіс командою `docker compose -f compose.yaml -f compose.spatial.yaml --profile spatial-research stop spatial-db`; том зберігається.

У pgAdmin створіть окреме підключення: хост `127.0.0.1`, порт `55433`, база `spatial_research`, користувач `dwh_user`, пароль із `.env`. Це не підключення до `logistics_dwh` на порту 55432. У Query Tool:

```sql
SELECT delivery_id, started_at, longitude, latitude,
       matched_shape_id, within_historical_shape, synthetic
FROM spatial_research.delivery_region
ORDER BY delivery_id
LIMIT 20;
```

```sql
SELECT shape_id, reference_year, ST_SRID(geom) AS srid,
       ST_IsValid(geom) AS geometry_valid
FROM spatial_research.historical_region;
```

Наступний крок — отримати й перевірити придатні межі районів або іншої актуальної територіальної одиниці, визначити правила неоднозначної межі та лише після цього поєднати просторову складову з часовим контекстом. Якщо надійних сучасних меж немає, слід зберігати історичну геометрію тільки як тестову.
