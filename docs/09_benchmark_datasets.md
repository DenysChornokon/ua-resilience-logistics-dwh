# 09. Синтетичні набори для benchmark

Генератор `scripts/generate_benchmark_deliveries.py` створює 10 000, 100 000 та 1 000 000 синтетичних доставок Києва в UTC-вікні `[2026-07-01, 2026-10-01)`. Менші файли є точними префіксами більшого, що дозволяє порівнювати обсяги на контрольованих вибірках. ID мають префікс `B-` і не збігаються з початковими 500 доставками.

Із кореня проєкту:

```powershell
python -m scripts.generate_benchmark_deliveries
```

Файли і `manifest.json` створюються в `data/synthetic/benchmark/`, який виключено з Git. Manifest містить seed, версію Python, розміри та SHA-256 для перевірки відтворення. За замовчуванням `seed=42`; значення можна змінити параметром `--seed`. При повторному запуску в ту саму папку скрипт відмовиться перезаписувати файли: для повторної перевірки використай іншу порожню папку з `--output-dir`.

Доставки, відстані й статуси синтетичні. Статуси генеруються незалежно від тривог; це не дані про фактичні затримки. Ці файли ще не завантажено в PostgreSQL: наявний завантажувач `scripts/load_dwh.py` призначений для початкового набору та навмисно не перезаписує заповнені таблиці. Для benchmark потрібне окреме ізольоване завантаження і контроль коректності. Одного масштабу доставок при фіксованих 371 тривозі недостатньо для висновків про всі типи навантаження.
