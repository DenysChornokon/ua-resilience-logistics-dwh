11.11.2026 на тому самому комп'ютері створено **нове ізольоване віртуальне середовище** на основі вже встановленого Python 3.13.3. У нього без використання кешу pip завантажено з публічного PyPI та встановлено залежності з `requirements.txt`. Перевірено всі **109** зафіксованих версій; `pip check` не виявив конфліктів. Нове середовище не використовувало пакети з наявного `.venv` проєкту чи пакети користувача.

У новому середовищі:

- відновлено три CSV з локальних первинних JSON і генератора; їхні байти збіглися з наявними файлами;
- із зафіксованого Git-коміту `cf1bec5e036496f650be333f28c1b86b8b747bc7` повторно розгорнуто схему й перевірки у двох нових ізольованих базах;
- успішно пройдено **87 автоматичних тестів**, перевірки SQL, сценаріїв, просторових результатів і оновлення версій; тестові ресурси баз прибрано.

Результат, версії пакетів і контрольну суму `requirements.txt` наведено в `reports/python_environment_reproduction_20261111.json`. Окремі звіти про дані та ізольовані бази — `reports/source_reproduction_new_venv_20261111.json` і `reports/cleanroom_new_venv_20261111.json`.

## Як повторити

У PowerShell із кореня проєкту. Потрібні Python 3.13, інтернет для встановлення пакетів, Docker Desktop і вихідні дані з документів 30–31. Наведені шляхи — приклади: **виберіть нові шляхи, яких ще не існує**, щоб не зачепити попередні файли. Особливо це стосується `--basetemp`: pytest видаляє вміст наявного каталогу за цим шляхом.

```powershell
py -3.13 -m venv C:\Temp\dwh-venv-01
& C:\Temp\dwh-venv-01\Scripts\python.exe -I -m pip --isolated install `
  --disable-pip-version-check --no-input --no-cache-dir --only-binary=:all: `
  --index-url https://pypi.org/simple -r requirements.txt
& C:\Temp\dwh-venv-01\Scripts\python.exe -I -m pip check
```

Далі можна окремо відновити й порівняти дані, запустити тести та перевірити свіжі бази:

```powershell
& C:\Temp\dwh-venv-01\Scripts\python.exe -B -m scripts.verify_source_reproduction `
  --output-dir C:\Temp\dwh-source-check-01
& C:\Temp\dwh-venv-01\Scripts\python.exe -B -m pytest -p no:cacheprovider -q `
  --basetemp C:\Temp\dwh-pytest-check-01
& C:\Temp\dwh-venv-01\Scripts\python.exe -B -m scripts.cleanroom_reproduce `
  --scratch-dir C:\Temp\dwh-database-check-01 --report C:\Temp\dwh-database-report-01.json
```

Остання команда використовує файли коду з поточного коміту Git, підготовлені CSV та геодані проєкту, а також Docker-образи, які вже є локально. Вона не використовує наявні бази; створені для перевірки ресурси видаляються після запуску. Деталі й перелік файлів — у документах 30 та 31.

## Обмеження

Перевірено новий `venv`, а не перевстановлення самого Python чи ОС і не інший комп'ютер. Фіксація версій у `requirements.txt` не фіксує криптографічні хеші завантажених пакетів; доступність і вміст зовнішнього реєстру в майбутньому можуть змінитися. Первинні JSON і геофайли потрібно зберігати окремо: вони виключені з Git. Повторне завантаження всіх першоджерел та великих benchmark-наборів цього разу не перевірялося. Синтетичні доставки й відключення та непідтверджені районні контури зберігають попередні обмеження дослідження.
